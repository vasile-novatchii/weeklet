# Releasing Weeklet

Releases are published to GitHub Releases by `.github/workflows/release.yml` when a `vMAJOR.MINOR.PATCH` tag is pushed. The APKs are signed with your release key, obfuscated, and split per ABI.

## 1. Prerequisites

A JDK providing `keytool`. The JBR bundled with Android Studio works. On macOS, `/usr/bin/keytool` is only a stub and fails without a JDK installed.

## 2. Create the keystore (once)

```bash
keytool -genkeypair -v -keystore weeklet-release.jks -alias weeklet -keyalg RSA -keysize 2048 -validity 10000
```

- Back up `weeklet-release.jks` and its passwords offline in at least two separate places. If the key is lost, installed users cannot be updated.
- Never commit the keystore or `android/key.properties`.

## 3. Set GitHub secrets

In the repo: Settings -> Secrets and variables -> Actions (or use `gh secret set`).

| Secret | Value |
|--------|-------|
| `ANDROID_KEYSTORE_BASE64` | `base64 -i weeklet-release.jks \| pbcopy` |
| `ANDROID_KEYSTORE_PASSWORD` | keystore (store) password |
| `ANDROID_KEY_PASSWORD` | key password |
| `ANDROID_KEY_ALIAS` | `weeklet` (the alias used above) |

If any secret is missing, the release job fails by design. A debug-signed APK is never published.

## 4. Tagging a release

1. Bump `version:` in `pubspec.yaml` (for example `1.1.0+2`). Raise the `+N` build number for every update.
2. Merge to `main`. `.fvmrc` must already be on `main`, since CI reads the Flutter version from it.
3. Tag and push:

   ```bash
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```

Rules enforced by the workflow:
- The tag (without `v`) must equal the pubspec version name (the part before `+`).
- The tagged commit must be reachable from `main`.
- Only three-part tags (`v1.2.3`) trigger a release. Two-part tags like `v1.1` do not.
- The release job re-runs analyze and tests before building.

## 5. What a release produces

- `weeklet-vX.Y.Z-arm64-v8a.apk`
- `weeklet-vX.Y.Z-armeabi-v7a.apk`
- `weeklet-vX.Y.Z-x86_64.apk`
- `SHA256SUMS`

Verify downloads with:

```bash
sha256sum -c SHA256SUMS
```

Release notes are generated by `scripts/changelog.sh` from conventional-commit subjects (`feat:`, `fix:`, `perf:`, `refactor:`, `docs:`, `test:`, `ci:`/`build:`, `chore:`) between the previous `vX.Y.Z` tag and the new one; other commits are listed under Other. Merge commits are skipped. Note that split-per-ABI builds offset the versionCode per ABI, so installed versionCodes differ from the `+N` in `pubspec.yaml`.

## 6. Debug symbols

The `--split-debug-info` output is uploaded as the workflow artifact `debug-symbols-vX.Y.Z` on the release run. GitHub caps artifact retention at 90 days, so download and archive it yourself:

```bash
gh run download <run-id> -n debug-symbols-vX.Y.Z
```

Deobfuscate a stack trace with:

```bash
flutter symbolize -i trace.txt -d <dir>
```

Be aware that this repository is public, so the artifact is not secret: anyone who can view the repo's Actions runs can download it. Symbols are not published as a release asset.

## 7. Before the first public tag

Manually install the arm64 release APK on a device and smoke-test PDF export and biometric unlock. Obfuscation and R8 can break these in ways tests do not catch.

## 8. Build problems

CI runs format check, analyze and tests, then a debug APK build, so most Gradle problems surface before tagging. R8/obfuscation and signing problems still surface only in the release job, after the tag is pushed. If a release fails, fix the problem, delete the tag, and re-tag.
