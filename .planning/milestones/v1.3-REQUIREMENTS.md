# Requirements: Weeklet

**Defined:** 2026-08-20
**Milestone:** v1.3 E2E Polish
**Core Value:** Users can always see where their money went - fast entry, accurate totals, no friction.
**Source:** E2E test findings list (18 items, 2026-08-20). Item numbers (#N) reference that list.

## v1.3 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### Income

- [x] **INC-05**: After adding an income entry for a different month/year than currently selected, the filter switches to that entry's month and year (#1)
- [x] **INC-06**: When adding income fails, the modal stays open and shows the error inline - below the input for field errors, as a general message otherwise (#10)
- [x] **INC-07**: Pull-to-refresh on the income screen reloads all data while preserving the active filter (#11)

### Statistics

- [x] **STATS-04**: The spending-by-category chart displays every category with spending in the period, including small amounts (e.g. 23 MDL/year) (#3)

### Categories

- [x] **CAT-01**: Adding a category during the first-expense flow (no categories exist yet) never overwrites a previously created category (#17)

### Amount Formatting

- [x] **FMT-01**: All amounts app-wide display in full format (e.g. 8570.8 MDL) - stats annual balance/expenses/income cards, income total, everywhere; compact K-notation removed (#2, #5, #18)
- [x] **FMT-02**: Amounts too long for their row/card are ellipsis-trimmed and show the full value in a long-press tooltip (default Material behavior) (#5, #18)

Note: FMT-01 exempts the annual grouped bar chart (touch tooltip and Y-axis keep compact K notation; accepted 2026-11-12, per 15-01/15-02 D-02/D-03).

Note: FMT-01 deliberately reverses the v1.1 "compact all amounts" decision (quick task 260430-qou).

### PDF Export

- [x] **EXP-05**: User can export the stats tab to PDF, honoring the active filter (#4)
- [x] **EXP-06**: PDF export supports the "all months" filter - exports every month present in the DB for the selected year; export button hidden when the selection has no data (#12)

### Localization

- [x] **LOC-02**: Language switch translates all remaining untranslated UI: filter month names, "Income vs Expenses" / "Income" / "Expenses" stats titles, "Total week" and "Week #" home labels (#6)
- [x] **LOC-03**: Date inputs format dates per app language - translated month names for RO/RU (e.g. "3 iunie, 2022"), UK format for EN (#15)

### Settings

- [x] **SET-06**: Tapping the app version card opens Flutter's built-in licenses page (#13)
- [x] **SET-07**: The "Reset all data" section has improved spacing at the bottom of settings (#14)

### UX

- [x] **UX-06**: Home screen shows a subtitle under the Expenses title with total income for the selected month/year, only when it exists (#8)
- [x] **UX-07**: The description input shows a placeholder appropriate to the screen using it (#9)
- [x] **UX-08**: The expenses list shows week groups newest-first with the current week always pinned at the top (e.g. current week 24, then 23, 22, ...) (#7)
- [x] **UX-09**: Bottom sheets render above the Android/iOS system navigation bar (#16)

| Multi-currency | Single currency per user; display setting only |

| New feature domains (budgets, recurring) | v1.3 is a fix/polish milestone scoped to e2e findings only |
